# Build PaperTrade Desk yourself

A watchlist is a manageable trading-themed CRUD project: save symbols, target prices, and notes; list them next to simulated quotes; change your plan; delete a saved item. The provided browser frontend lets you exercise your own backend. Every displayed quote is a deterministic fixture, not a current market price.

The starter and reference are separate implementations. Work in `trading/starter-api.cjs`. Open the reference only after making a first attempt. These are invented practice tasks; they are not Goldman assessment questions.

## Run your starter

From the repository root:

```sh
npm ci
npm run trading:start
```

Open <http://127.0.0.1:3101>. The page and simulated quotes work immediately. Watchlist handlers return `501` until you implement them; the page labels those responses as starter tasks.

In another terminal:

```sh
npm run trading:check
```

The contract tests are your specification. They initially fail for the five missing CRUD handlers. Read the assertion messages and implement one route at a time. Stop the starter with Ctrl+C before running the reference on the same port:

```sh
npm run trading:reference
npm run trading:verify
```

`npm test` checks the existing lab plus completed reference implementations. It does not require the unfinished starter or deliberately buggy exercises to pass.

## Data and HTTP contract

| Field | Rule |
| --- | --- |
| `symbol` | Required on create; trim and uppercase; 1–6 letters, optionally a dot and 1–2 suffix letters, such as `BRK.B` |
| `targetPriceCents` | Optional positive integer, at most 100,000,000 cents; defaults to `null`; an explicit `null` clears an existing target |
| `notes` | Optional string, at most 300 characters; defaults to an empty string |
| `id`, `createdAt` | Generated by the store; clients cannot set or replace them |

Symbols are unique after normalization. Store cents as integers so a target of $187.25 is represented by `18725`. Duplicate symbols return `409`; malformed input returns `400`. In a patch, omitting a target keeps it; sending `null` clears it. Sending an empty string for notes clears the notes.

| Request | Expected result |
| --- | --- |
| `POST /api/watchlist` | `201` with the saved item and its generated ID |
| `GET /api/watchlist` | `200` with a list; an empty list is valid |
| `GET /api/watchlist/:id` | `200` with one item, or `404` |
| `PATCH /api/watchlist/:id` | `200`; preserve omitted fields; reject an empty or invalid patch |
| `DELETE /api/watchlist/:id` | `204` with no body, or `404` |

Fixture prices are exposed by `GET /api/quotes`; the server mode is exposed by `GET /api/mode`. The frontend uses these read endpoints without needing a market-data provider.

## Build in four sessions

1. **Read and create, 45 minutes.** Trace the frontend request into a handler. Implement list, create, and read-one. Normalize symbols, validate the request, and return the actual saved item. First verify a single creation, then duplicates and bad inputs.
2. **Update and delete, 45 minutes.** Implement partial updates that keep the existing notes and ID when only the target changes. Make nonexistent IDs return `404`. Delete an item and prove that reading it afterward fails.
3. **Explain persistence, 30 minutes.** Follow the shared `src/store.cjs` into the SQLite statement. Restart the local server and check that saved items survive. Explain the difference between request validation, storage, and the HTTP response.
4. **Make it yours, 45 minutes.** Add filtering by symbol or a `strategy` field. Write a behavior test first, then validation, then the handler, then the form. Keep the existing tests passing.

For each session, write three sentences: what input you sent, where the state changed, and what the caller received. Commit one completed behavior after checking the diff and relevant tests.

## Next project: a trade journal

After watchlist CRUD passes, add `/api/trades` with create/list/read/update/delete. Start with these fields: `symbol`, `side` (`buy` or `sell`), positive whole `quantity`, positive integer `priceCents`, an explicit UTC timestamp, and `notes`.

Start with a **journal of fictional records**. Editing a row changes a journal entry. Computed holdings, realized profit, and simulated order execution are later features with additional rules and tests. Define sorting, fees, repeated submissions, and overselling before adding those calculations.
