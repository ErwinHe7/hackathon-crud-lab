# Hackathon CRUD lab

A runnable Node.js practice API and debugging exercises, with code walkthroughs of **Awesome Todo Maintainer** and **FinForge**. The practice API is original educational code; the hackathon authors' work remains in attributed forks.

Practice materials and fork fixes were prepared with Codex assistance. The original hackathon projects are credited below.

## Start here

Install Node.js **22.13 or later**, then:

```sh
git clone https://github.com/ErwinHe7/hackathon-crud-lab.git
cd hackathon-crud-lab
npm ci
npm test
npm run demo
```

`npm run demo` starts a temporary local API, demonstrates task and report CRUD, and shuts it down. It uses an in-memory SQLite database. It needs no Notion token, MongoDB account, or external API.

For hands-on requests, run `npm start`. The API listens on `http://127.0.0.1:3100` and stores practice records in `data/practice.db`. Node 22 may print a warning because its built-in SQLite module is experimental. Use synthetic records; this teaching server has no login or access control.

Read [the learning guide](docs/LEARNING.md), [request flows](docs/REQUEST-FLOWS.md), and [debugging exercises](docs/EXERCISES.md).

## API

Both `/api/tasks` and `/api/reports` support:

| Operation | Request | Response |
| --- | --- | --- |
| Create | `POST /api/tasks` with JSON | `201` and saved record |
| List | `GET /api/tasks?status=todo&q=trace` | `200` and matching records |
| Read one | `GET /api/tasks/:id` | `200`, or `404` if missing |
| Update fields | `PATCH /api/tasks/:id` with JSON | `200` without losing omitted fields |
| Delete | `DELETE /api/tasks/:id` | `204`, or `404` if missing |

Task example: `{"title":"Trace a request","priority":"high"}`. Task statuses: `todo`, `doing`, `done`. Report example: `{"title":"Mock phishing","website":"https://example.test","fraudType":"Phishing"}`. Report statuses: `new`, `reviewing`, `resolved`. IDs and creation timestamps are generated by the server. Invalid input returns `400`.

PowerShell example, after `npm start` in a separate terminal:

```powershell
$task = Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:3100/api/tasks' -ContentType 'application/json' -Body '{"title":"Trace a request","priority":"high"}'
Invoke-RestMethod -Method Patch -Uri ('http://127.0.0.1:3100/api/tasks/' + $task.id) -ContentType 'application/json' -Body '{"status":"done"}'
Invoke-RestMethod -Uri ('http://127.0.0.1:3100/api/tasks/' + $task.id)
Invoke-RestMethod -Method Delete -Uri ('http://127.0.0.1:3100/api/tasks/' + $task.id)
```

## Validation and contributions

- Practice API: 12 passing local HTTP/SQLite tests.
- Your forks: 17 passing isolated regression tests, with Notion, MongoDB, VS Code, and Axios replaced by test doubles. The tests reproduced 10 failures before the fixes; three network-failure checks were added afterward.
- Exercises: three deliberately failing checks under `npm run exercise`; the same three checks pass against the reference answers under `npm run solutions`.
- Original integration deployments and live accounts were not exercised. The legacy applications need their own configuration and additional integration testing before deployment.

The original lab commits are on `main`. GitHub counts qualifying commits on a standalone repository's default branch when the author email is connected to the account. Fork commits require upstream merging to count; graph updates can take up to 24 hours. [GitHub's contribution rules](https://docs.github.com/en/account-and-profile/how-tos/contribution-settings/troubleshooting-missing-contributions).
